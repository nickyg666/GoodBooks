2. PROGRESS BAR AUTO-HIDE GLITCH ✅ FIXED
================================================================================
Problem:   Progress bar won't disappear after metadata refresh completes
Locations: 
  - app.py (lines 4133-4146)
  - templates/base.html (lines 139-197)
  - static/desktop.css (lines 155-195)
  - static/kindle.css (lines 87-113)

Root Causes:
  1. 30-second sleep delay keeping bar visible
  2. CSS positioning at top: 100% (off-screen) instead of top: 0
  3. No proper EventSource cleanup
  4. Multiple conflicting CSS states (.hidden, .collapsed, .active)

Fixes Applied:
  1. REMOVED: time.sleep(30) - now hides immediately
  2. FIXED CSS state machine:
     - Default: top: 100% (off-screen below), display: none
     - .active: top: 0 (in viewport), display: flex
  3. ADDED: EventSource.close() when active: false received
  4. REMOVED: .hidden and conflicting .collapsed states
  5. Simplified: Only two states now (.active present/absent)

Result:
  ✅ Progress bar slides in from top
  ✅ Shows progress with percentage and ETA
  ✅ Immediately hides when refresh completes
  ✅ No flickering, clean state transitions

6. STALE IMAGE CACHE 💾 DOCUMENTED
================================================================================
Problem:   Old/broken cover URLs cached, showing broken images
Location:  data/cover_cache/

Solution:
  Clear entire cache:
    rm -rf /usr/local/bin/GoodBooks/data/cover_cache/*
  
  Clear old cache (>30 days):
    python3 -c "from cover_cache_manager import get_cache_manager; \
                get_cache_manager().cleanup_old_cache(1)"
  
  Clear specific image:
    python3 -c "from cover_cache_manager import get_cache_manager; \
                get_cache_manager().clear_cover('URL')"

Cache Details:
  - Directory: data/cover_cache/
  - Files: MD5 hashes of URLs (e.g., a3c4d5e6f7g8h9i0j1k2l3m4.jpg)
  - Min width cached: 300px
  - Quality: 95% JPEG
  
Result:
  ✅ Clear cache when you see stale images
  ✅ Fresh covers fetched on next access
